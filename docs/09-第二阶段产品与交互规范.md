# 第二阶段产品与交互规范

## 1. 本阶段目标

在第一阶段稳定的发布、投票、刷新与回复链路上，加入完整人物卡、每轮 6-8 人参与、人物间一次性交锋，以及好友列表到历史朋友圈详情的浏览路径。

本阶段不制作视角地图或结果页。历史朋友圈图片直接选择网络平台上的历史照片、绘画、版画或时代环境图，下载到项目本地使用；不要求每张图都是事件现场，但不得出现明显时代错位。

## 2. 唯一人物卡版本

本阶段以用户于 2026-09-22 提供的“14 位历史人物完整人设卡”为唯一权威。它覆盖此前的旧 ID、签名、IP、关键词和分组。

固定 ID 如下：

- 核心冲突组：`luxun`、`wuzetian`、`nietzsche`、`marx`、`franklin`
- 视角补充组：`socrates`、`buddha`、`wangyangming`、`beauvoir`、`zhangailing`
- 中国历史组：`yingzheng`、`kangxi`
- 氛围组：`libai`、`einstein`

旧 ID 迁移关系由代码维护，保证此前保存在 localStorage 的动态仍能找到人物：

```json
{
  "lu_xun": "luxun",
  "wu_zetian": "wuzetian",
  "shakyamuni": "buddha",
  "qin_shihuang": "yingzheng",
  "li_bai": "libai",
  "karl_marx": "marx",
  "benjamin_franklin": "franklin",

  "simone_de_beauvoir": "beauvoir",
```

## 3. 每轮参与人物抽取

1. 用户最多 @5 位好友，被 @ 的人物必定参与并生成主评论。
2. 每次发布先随机决定目标人数，目标为 6、7 或 8。
3. 从未被 @ 的剩余人物中无重复随机补足至目标人数。
4. `participants` 顺序先放被 @ 人物，再放随机补入人物，便于优先展示。
5. 未 @ 任何人时，从全部 14 人中随机抽取 6-8 人。
6. 所有参与者都参与点赞、投票、主评论、评论标签和人物互动导演。
7. 苏格拉底可以参与但不投 A-D；其他人物在 mock 阶段投票选项必须合法。
8. 随机函数作为参数注入纯逻辑函数，自动测试可使用固定随机序列复现结果。
9. 若发布时没有投票组件，人物仍参与点赞、评论和人物间互动，只是不生成投票。

## 4. AI 互动导演与一来一回

人物主评论生成后，只调用一次 `interaction_director` 任务。该任务一次性读取本轮人物卡、主评论、`agreeTags` 与 `disagreeTags`，由 AI 判断语义相关性，而不是做字符串完全匹配。

导演输出：

```json
{
  "interactions": [
    {
      "fromCharacterId": "franklin",
      "toCommentId": "comment_nietzsche",
      "toCharacterId": "nietzsche",
      "type": "rebuttal",
      "strength": 2,
      "matchedIdeas": ["理想主义", "反抗平庸"]
    }
  ]
}
```

硬规则：

- `type` 只允许 `rebuttal`、`agreement`、`question`、`aside`。
- 每条朋友圈全局最多选择一组人物互动，不允许四五个人同时围攻一条主评论。
- 导演若返回多个候选，系统只保留语义强度最高的一组；同强度时保留最先返回的一组。
- 同一人物不能回复自己。
- 第一回合：唯一挑战者回复某位人物的主评论。
- 第二回合：原评论作者必须针对这位挑战者的具体质疑，维护、澄清或修正自己的观点。
- 第二回合结束后线程终止，不允许挑战者再回第三句，也不允许第三人插入。
- 苏格拉底优先对确定性结论发出 `question`。
- 释迦牟尼不参与争吵；只允许温和的 `agreement` 或 `aside`，也可以完全不回复。
- AI 输出无效时，过滤无效项；全部无效时安全降级为只有主评论，不为了热闹硬凑多人回复。
- mock 导演使用固定、可复现的语义示例来跑通 UI，后续只替换 `callAI` 内部实现。

## 5. 用户回复人物

- 用户回复某人物时仅带：完整人物卡、当前问题、该人物与用户最近 6 条消息，以及用户明确提到的其他评论全文。
- 人物只回复用户，不继续回复别的人物。
- 每个用户-人物对话独立计数。
- 第 10 个用户轮次后，人物返回固定冷却句：“我已经把该说的都说了。你该问自己了。”
- 人物回复仍进入待刷新池，用户点击刷新后才显示。

## 6. 好友列表

- 信息流左侧边缘增加一个“好友”拉手按钮；点击或从左边缘向右滑动打开抽屉。
- 拉手采用向画布外侧翻出的书签形态：原白底、浅灰描边、圆角和浅阴影保持不变，仅将外壳左右镜像，圆角、描边开口和阴影方向随之翻转；好友图标与“好友”文字不镜像，仍保持正常可读方向。
- 抽屉默认隐藏，覆盖在信息流上方，背景有半透明遮罩。
- 当前 14 位好友固定排序，后续可以扩展到 20 人；本阶段不支持新增或删除。
- 每项显示圆形头像、昵称和个性签名。
- 点击好友后关闭抽屉并进入好友预览页，不直接进入完整历史朋友圈详情。

## 7. 好友预览页

- 参考微信联系人资料页，顶部显示返回、头像、昵称、签名和 `IP：地区`。
- 保留“发消息”按钮，但禁用，并显示“私聊功能后续开放”；删除语音视频通话入口。
- “朋友圈”区域横向显示最近 3-4 条历史朋友圈配图缩略图。
- 点击朋友圈区域或任一缩略图，进入该好友的历史朋友圈详情页。

## 8. 历史朋友圈详情页

- 顶部是人物第一条历史朋友圈配图形成的封面，叠加人物头像、昵称与签名。
- 展示 IP 和 3 个人生关键词。
- 时间线按人物卡 `moments` 数组顺序展示；日期只显示年份或原始时代文字，不显示月日。
- 每条朋友圈显示日期、静态文案和一张本地历史配图。
- 图片仅作时代氛围或地点辅助，不宣称为事件现场。
- 若人物参与当前最新问题，页底展示其投票选项和主评论理由。
- 若人物在最新问题评论区出现，显示“回到 TA 的评论”按钮；点击返回信息流，滚动到对应评论并短暂高亮。

## 9. 苏格拉底补充朋友圈

用户批准补足第三条，采用《克里同篇》情节改写：

> 公元前399年：朋友来劝我越狱。我拒绝了。一个人不能只在法律对自己有利时才尊重它。

该文案标记为史料情节改写，不是苏格拉底逐字原话。

## 10. 页面状态与返回

页面状态允许：`feed`、`composer`、`friendPreview`、`friendMoments`。好友抽屉是覆盖层，不是独立页面。

- 好友预览返回信息流。
- 历史朋友圈详情返回好友预览。
- “回到 TA 的评论”直接返回信息流并定位。
- 发布、刷新、@好友、投票、评论点赞和用户回复保持第一阶段规则不变。
