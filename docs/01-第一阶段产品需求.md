# 第一阶段产品需求

> 历史说明：本文件保留第一阶段边界。第二阶段新增或冲突规则以 `docs/09-第二阶段产品与交互规范.md` 为准。

## 1. 产品目标

制作一个移动端优先、在电脑中也可自然预览的“古人朋友圈”。本阶段只验证发布、@好友、投票、刷新、点赞、评论及用户回复的完整链路，不接入真实 AI，也不填充最终历史人物内容。

产品主角固定为“我”，头像和朋友圈背景均为项目预设，不允许改名、更换头像或更换背景。

## 2. 本阶段范围

### 必须完成

- 打开网站直接进入朋友圈信息流。
- 右上角加号展开“发布朋友圈”“刷新朋友圈”。
- 发布内容仅支持手动输入文字，不支持上传或解析图片。
- 发布时可 @ 特定好友，最多 5 人。
- 发布时可设置投票题目和 2-4 个自定义选项。
- 投票选项自动以 A、B、C、D 标记。
- 发布完成后动态立刻出现，但历史人物互动不可见。
- 点击刷新后，一次性出现 mock 点赞、人物投票和人物评论。
- 点赞区只展示历史人物头像，不展示点赞者文字名单。
- 评论展示人物头像、真实姓名、正文和 `IP：地区`，不显示时间。
- 每条评论右侧有线性爱心与评论气泡按钮。
- 爱心点击后变粉红，再点取消。
- 点击人物头像、姓名、评论正文或评论按钮，可输入回复。
- 用户回复后，人物被动回复一条；新回复先进入待刷新池，再次刷新后显示。
- 所有运行数据刷新浏览器后仍保留在本地。

### 当前人物素材与占位内容

- 好友库当前包含 14 人：鲁迅、武则天、尼采、苏格拉底、释迦牟尼、嬴政、康熙、李白、马克思、富兰克林、王阳明、波伏娃、张爱玲、爱因斯坦。
- 14 位好友头像使用用户提供的图片，集中放在 `public/assets/好友头像/`，文件以人物姓名命名。
- 固定用户“我”的头像为 `public/assets/user/avatar.jpg`，不可修改。
- 人物真实人设尚未填写，mock 点赞、投票、评论和回复继续使用明显占位文案。
- 朋友圈背景仍为临时素材，后续在固定路径覆盖即可。

## 3. 本阶段不做

- 不制作“消息”“我的”两个底部栏目。
- 不支持用户自定义资料。
- 不支持图片上传、权限申请、多模态识图。
- 不接数据库、登录、云端同步或真实 AI。
- 第一阶段不制作人物资料页、好友侧边栏和结果页；第二阶段已新增人物资料与好友侧边栏，但仍明确不制作结果页。
- 不让历史人物互动自动逐条出现。
- 不做多轮人物互相争论；本阶段只验证用户和人物的一问一答刷新链路。

## 4. 核心体验规则

刷新是唯一“收取历史人物新互动”的方式。无论后台 mock 内容是否已经生成，只要用户没有主动点击“刷新朋友圈”，点赞、投票、评论与人物回复都不能出现在页面上。

首次刷新一次性展示该动态当前全部待收取互动，以降低复杂度并保证比赛演示稳定。

## 5. 验收定义

一位不了解代码的人可以在浏览器中独立完成：进入朋友圈 → 点击加号 → 发布文字和投票 → 选择 @ 好友 → 发布 → 看到暂时安静的动态 → 刷新 → 看到人物头像点赞、投票与评论 → 点赞评论 → 回复人物 → 再刷新 → 看到人物回复。
