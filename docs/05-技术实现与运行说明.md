# 技术实现与运行说明

## 1. 技术栈

- React 18
- Vite 5
- 原生 CSS（避免依赖官方平台不一定支持的 Tailwind 构建配置）
- Vitest + Testing Library
- localStorage 本地持久化
- Vite 本地服务端 `/api/ai` 代理已配置 OneAPI，密钥不进入浏览器
- 无数据库、无路由库、无图标库；图标使用项目内 React SVG 组件

选择原生 CSS 是为了让官方平台更容易复刻，也便于最终导出单页 HTML 时迁移。页面切换使用 React 状态完成。

## 2. 目录职责

```text
古人朋友圈模拟器/
├── CLAUDE.md                     # AI 开发工作总指引
├── docs/                         # 产品与复刻标准
├── 开发日志/                     # 每日开发记录
├── public/assets/user/           # 固定用户“我”的头像、背景
├── public/assets/好友头像/        # 以人物姓名命名的好友头像
├── public/assets/moments/         # 14 人共 42 张本地历史朋友圈图片
├── src/components/               # 纯界面组件
├── src/data/characters.json      # 唯一人物库
├── src/services/callAI.js        # 唯一 AI 接口
├── src/utils/                    # 发布、刷新、投票等纯逻辑
└── src/App.jsx                   # 页面状态与总流程
```

## 3. 本地运行

```bash
npm install
npm run dev
```

浏览器打开终端显示的本地地址。构建检查：

```bash
npm test
npm run build
```

开发模式会自动启用真实 OneAPI 生成人物评论；一次发布需要并行生成 6-8 条评论和少量人物互动，通常需等待数十秒。OneAPI 暂不可用时会自动使用仍与当前问题相关的人物专属离线回复。

## 4. 素材替换

- 固定用户头像为 `public/assets/user/avatar.jpg`，产品内不可更改；仅在用户明确提供替代素材时覆盖该文件。
- 将固定朋友圈背景覆盖为 `public/assets/user/cover.svg` 或同名图片。
- 人物头像放入 `public/assets/好友头像/`，文件名使用人物显示名，如 `鲁迅.jpg`；同时确保 `characters.json` 的 `avatar` 字段一致。
- 历史朋友圈图片固定放在 `public/assets/moments/<人物ID>/01-03.jpg`，来源登记见 `docs/12-历史朋友圈图片来源登记.md`。
- 素材建议正方形头像不低于 256×256，封面建议不低于 1200×720。

## 5. 替换真实 AI

官方平台迁移时保留 `src/services/callAI.js` 的调用签名，并将 `server/` 下本地代理替换为平台安全服务端函数：

1. 保留现有函数签名。
2. 把 `systemPrompt`、`userMessage`、`history` 和 `task` 传给平台模型。
3. 要求模型只输出规定 JSON。
4. 解析失败时回退到 mock 或友好错误，不能让页面空白。
5. API 密钥不得写进前端仓库；本地版由服务端读取 CodexOne 配置，正式版通过平台安全变量或服务端代理注入。

## 6. 开发原则

- 先改 `docs/` 中对应标准，再改代码，防止母版与实现分离。
- 任何人物专属内容不得硬编码进组件。
- 新的 AI 场景仍走 `callAI`，不得在组件内直接请求模型。
- 保持刷新收取互动的产品规则，不加入自动轮询。
- 每次开发结束更新当天日志和 `docs/07-验收清单.md`。
