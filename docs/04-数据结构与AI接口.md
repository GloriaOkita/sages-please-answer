# 数据结构与 AI 接口

## 1. 人物卡

人物静态数据只放在 `src/data/characters.json`。后续增加人物或替换人设时，不修改组件代码。

```json
{
  "id": "luxun",
  "name": "鲁迅",
  "avatar": "/assets/好友头像/鲁迅.jpg",
  "signature": "从来如此，便对么？",
  "ip": "上海",
  "keywords": ["关键词1", "关键词2", "关键词3"],
  "group": "core_conflict",
  "coreValue": "不要在麻木中假装活着。",
  "personality": "狠、短句、匕首、不绕弯、偶尔冷幽默",
  "socialTendency": "对麻木、自欺、看客心态会主动扎",
  "forbidden": "绝对不说温和的、安慰的、和稀泥的话",
  "agreeTags": ["反抗", "清醒", "直面现实", "行动"],
  "disagreeTags": ["麻木", "自欺", "看客", "逃避"],
  "replyStyle": "短句为主，不超过三行。",
  "moments": [{ "id": "luxun_1", "date": "1906年", "content": "静态文案", "image": "/assets/moments/luxun/01.jpg", "sourceId": "luxun-era" }]
}
```

`ip` 只写地区名，页面统一拼成 `IP：地区`。`group` 预留值为 `core_conflict`、`perspective`、`chinese_history`、`atmosphere`。

当前 14 位好友的完整权威卡见 `src/data/characters.json` 和 `docs/13-完整人物卡.md`。签名及朋友圈必须静态读取，不接 AI 生成。

## 2. 发布草稿

```json
{
  "content": "我正在纠结的问题与处境",
  "mentionedCharacterIds": ["luxun"],
  "poll": {
    "question": "我该选择哪一种？",
    "options": [
      { "id": "A", "text": "选项一" },
      { "id": "B", "text": "选项二" }
    ]
  }
}
```

投票可为空；一旦存在，必须包含题目和 2-4 个非空选项。选项 ID 只使用 A、B、C、D。

## 4. 评论与回复

所有评论必须有唯一 ID，不能依赖数组序号。

```json
{
  "id": "comment_时间戳_人物ID",
  "type": "character_comment",
  "characterId": "luxun",
  "content": "鲁迅的占位评论",
  "likedByUser": false,
  "replies": [
    {
      "id": "reply_时间戳",
      "type": "user_reply",
      "authorId": "me",
      "targetCharacterId": "luxun",
      "content": "用户回复"
    },
    {
      "id": "reply_时间戳_人物ID",
      "type": "character_reply",
      "characterId": "luxun",
      "targetUserId": "me",
      "content": "鲁迅对我的占位回复"
    }
  ]
}
```

## 5. callAI 单一入口

所有未来的真实 AI 调用必须经过：

```js
async function callAI(systemPrompt, userMessage, history = [], task = "comment")
```

`task` 支持：

- `initial_interactions`：返回点赞、投票、主评论。
- `interaction_director`：一次性返回人物间语义互动关系与回复。
- `reply_to_user`：返回指定人物对用户的一条回复。

第一阶段返回 mock 数据。替换真实模型时，不改变调用方和页面组件，只替换 `src/services/callAI.js` 内部实现。

```json

}
```

## 7. 本地保存

- localStorage 键：`ancient-moments-state-v2`，读取时兼容并迁移 `v1`。
- 保存已发布动态及可见、待刷新互动。
- `generationStatus` 使用 `generating | ready | failed`：`generating` 表示后台仍在生成，`ready` 表示回应已生成，`failed` 表示可在下一次手动刷新时自动重试。
- 恢复 `generating` 或重试 `failed` 时必须复用原 `participantIds`，不得重新随机抽取人物。
- 后台生成完成时只合并 `pendingInteractions`，不得用生成开始时的旧快照覆盖用户刷新、点赞或回复产生的新状态。
- 不保存弹窗开关、菜单开关等瞬时界面状态。
- 数据版本变化时更新键名，避免旧结构导致页面报错。
