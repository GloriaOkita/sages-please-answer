# 第一阶段验收清单

## 主界面

- [x] 打开即进入朋友圈，没有消息、我的等无效入口。
- [x] 固定封面、固定头像和名字“我”清晰显示。
- [x] 右上角加号可开关菜单。
- [x] 菜单包含且只包含发布朋友圈、刷新朋友圈。

## 发布

- [x] 正文为空时不能发表。
- [x] 不存在图片上传入口。
- [x] @好友弹窗在电脑屏幕正中，背景变灰，可关闭。
- [x] 最多选择 5 人，满额后其他选择变灰，取消后恢复。
- [x] 投票题目必填，默认 2 项，最少 2 项，最多 4 项。
- [x] 投票自动显示 A/B/C/D，可编辑、增加、删除。
- [x] 题目或任一选项为空时投票完成按钮不可用。

## 刷新与互动

- [x] 发布后动态立即可见，但无人物点赞、投票和评论。
- [x] 第一次刷新后互动一次性全部出现。
- [x] 点赞只显示头像，不显示姓名文字列表。
- [x] 评论显示头像、姓名、内容、`IP：地区`，不显示时间。
- [x] 评论右侧爱心可切换粉红色。
- [x] 评论右侧是带三个点的线性气泡，不是苦脸或 emoji。
- [x] 点击头像、姓名、正文、气泡均可回复。
- [x] 用户回复立即显示，人物回复在下一次刷新后显示。
- [x] 没有待刷新内容时有明确提示。

## 数据与稳定性

- [x] 刷新浏览器后已发布动态仍存在。
- [x] 14 位具名好友来自 `characters.json`，顺序与用户提供的头像顺序一致。
- [x] 14 张好友头像集中放在 `public/assets/好友头像/`，文件名为人物姓名。
- [x] 用户“我”使用固定的 `public/assets/user/avatar.jpg`，界面无头像更换入口。
- [x] 所有 AI 模拟调用来自唯一 `callAI` 函数。
- [x] 页面在 375px、430px 和普通电脑宽度下均可操作。
- [x] 测试通过，生产构建成功，浏览器控制台无明显错误。

## 第二阶段验收

- [x] 最新完整人物卡字段和四层分组为 5/5/2/2，旧 ID 可迁移。
- [x] @ 0、3、5 人时，被 @ 人物必入选，最终均为 6-8 位且无重复。
- [x] 主评论包含 `commentTags`，人物互动只调用一次导演任务。
- [x] 人物每人最多回复两条，不回复自己，互动只有一层。
- [x] 苏格拉底不投票并优先反问；释迦牟尼不争吵。
- [x] 用户第 10 轮触发冷却句。
- [x] 左侧好友抽屉列出 14 人头像、姓名和签名。
- [x] 信息流支持点击左侧拉手或从屏幕左边缘右滑打开好友抽屉。
- [x] 好友预览显示签名、IP、关键词和朋友圈缩略图，“发消息”禁用。
- [x] 详情页显示 3 条历史朋友圈，第一张图兼作封面。
- [x] 最新问题参与者可查看投票与评论，并能返回定位高亮。
- [x] 42 张历史图片均为本地文件，来源和许可已登记。
- [x] 不存在视角地图或结果页。
- [x] 第二阶段全量测试、构建、桌面及移动浏览器验收通过。

## 角色语料与隔离验收

- [x] `docs/人物卡/` 有 14 份独立人物 Markdown，路径与 `characters.json.personaFile` 一一对应。
- [x] 每份人物卡均含原文语料、可迁移风格、生成策略、正反例和输出自检。
- [x] 主评论每人独立调用，只加载当前人物卡，用户内容按不可信数据处理。
- [x] 互动导演只输出关系，不写台词；最终台词由回复者独立人物卡生成。
- [x] 用户回复只带当前人物卡和最近 6 条专属对话，第 10 轮冷却。
- [x] 输出检查 ID、投票、标签及助手套话，失败重试一次或人物专属回退。
- [x] 本地 mock 的 14 种声音均读取用户问题，无“占位评论”或统一模板。
- [x] 使用多个彼此差异显著的开放问题测试；测试题不形成主题分类或模板路由，主要人物语言结构仍可明显区分。

## 动态问题响应验收

- [x] 本地 `/api/ai` 通过服务端安全调用已配置 OneAPI，前端不包含密钥。
- [x] 同一人物面对两个同类别、不同矛盾的问题时生成不同回复。
- [x] 回复至少引用原问题或投票选项的一项具体信息。
- [x] 回复不复制完整问题、不用大段篇幅复述用户原文，只保留必要关键词。
- [x] 短追问继承当前朋友圈问题，不被当成孤立问题。
- [x] OneAPI 失败时启用人物专属离线降级，降级内容仍与具体问题相关。
- [x] 发布生成期间按钮禁用并显示明确等待提示。
- [x] 真实 OneAPI 已用“高薪长通勤”和“升职隐瞒错误”两题验证，同一人物输出明确不同。
- [x] 浏览器完整发布生成 6-8 位人物评论时，人物均围绕本次问题的具体矛盾作答。
- [x] 点击发表后动态立即进入信息流，AI 在后台生成，不再因等待模型表现为发布失败。

## 一来一回互动验收

- [x] 每条朋友圈最多只有一位挑战者回复一条主评论。
- [x] 导演返回多个候选时只保留语义强度最高的一组。
- [x] 原主评论作者会针对挑战者的具体回复生成一条辩护。
- [x] 每个互动线程严格只有“挑战 + 辩护”两条，之后终止。
- [x] 不允许第三人插入，也不允许四五个人同时回复一个人。
